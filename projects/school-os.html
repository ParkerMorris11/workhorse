School OS

A system I built for my own BYU semester. It syncs Canvas and my lecture notes into one database, then serves the same data to a web dashboard, a desktop app, and ChatGPT.

StatusPiloted on 4 BYU courses
StackCloudflare Workers, D1, Auth0, React, Tauri, MCP
RoleDesigned and built
01 / The problem

The semester lives in too many places.

Assignments, due dates, and grades are in Canvas. Lecture notes and transcripts are in a folder on my Mac. Keeping up with both, for every course, is repeated work. School OS pulls them into one place on a schedule.

One API, three clients.

03 / How it works

From Canvas to one screen.

  1. 01

    Scheduled Canvas sync

    A cron trigger (*/30 * * * *) queues a SyncService run for each pilot course. One run per course at a time, batch size 1, up to 3 retries. Canvas is read with a read-only token.

  2. 02

    Notes from the Mac

    A launchd job runs vault-sync.mjs every 30 minutes and uploads only the Markdown notes that changed. Its API key is read from the macOS Keychain.

  3. 03

    Snapshot publishing

    Each sync writes a complete run into D1, then sets published_run for the course. Readers only ever see a finished snapshot, never a half-written one.

  4. 04

    One authenticated API

    A single Worker router serves /api/tools, /api/vault/upload, and /mcp. Every request carries an Auth0 RS256 token, verified with jose against the JWKS.

  5. 05

    Three ways to read it

    A React dashboard (Today, Due, Grades, Tests, Settings), a Tauri desktop app behind Touch ID, and a ChatGPT connector over MCP.

04 / Guardrails

People stay in control.

Read-only Canvas.

The Canvas token can read, not write. School OS never changes anything in a course.

Submissions stay manual.

It shows what's due. Turning work in is still done by me, in Canvas.

Nothing runs until you press send.

Dashboard links open a prefilled ChatGPT prompt. It waits for me to send it.
